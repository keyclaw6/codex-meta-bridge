## Known defects — OPEN

### 1. `interrupt_turn` is a no-op in practice — highest priority

Files/symbols: `src/mcp.mjs` (`interrupt_turn`) and
`src/owned-consumer.mjs` (`OwnedConsumer.interruptTurn`).

The tool returns `ok: true`, but the live Test D 600-second `D-SLEEP` was not
aborted and ran to completion. A wedged mission currently requires a daemon
restart. The next agent should trace whether `AbortController.abort()` reaches
the SDK stream and add a real integration test that proves early process/turn
termination.

### 2. `ack_callback` restart persistence fails in the live system

Files/symbols: `src/mcp.mjs` (`ack_callback`) and `src/inbox.mjs`
(`markCallbackAcked`, `ackedCallbacks`).

The certification report says acknowledged callbacks reappeared after daemon
restart despite the tool description promising persistence. Treat this as an
open runtime regression. Note that the current code appends acknowledgements to
`callbacks-acked.jsonl`; that implementation conflicts with the observed report,
so the failure mode needs a restart-level reproduction rather than an assumption
that the code is purely in-memory.

### 3. Vendored Codex console leaks a black window

File/symbol: `src/codex-cli.mjs` (`spawnVisibleCodexWindow`).

`vendor-console-hidden=no`. A visible, elevated black console has appeared with
a title pointing into
`node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-*\bin\codex.exe`.
The rollout can continue while this window remains unreadable. The deterministic
working visibility path is the rollout viewer.

### 4. MCP client tool-manifest cache

File/surface: `src/mcp.mjs` tool registration versus the Hyperagent MCP client
connection.

The daemon registers `start_visible_cli_mission`, but an already-connected
Hyperagent client may continue to list the older tool manifest until it
reconnects.

### 5. Intermittent Streamable HTTP transport flap

Files/symbols: `src/mcp.mjs` (`startHttp`, ingress event handlers).

Observed error:


The detail was empty and failed calls left no audit entry. The mitigation is
`keepAliveTimeout=1200000` and `headersTimeout=1205000`, with ingress logging for
the next occurrence. The stale-socket/Tailscale hypothesis remains unproven.

## The visible-window finding

A plain human launch:

```cmd
cmd.exe /k codex
```

does paint an interactive TUI. However, a fresh TUI does not create a rollout or
thread ID until a human submits its first prompt. Without that ID, the bridge
cannot register the session or deliver the first steering message. Therefore an
agent-steerable session and a fresh human-visible TUI are mutually exclusive
unless the human types the first prompt. The rollout viewer is the working
resolution because it can display any already-existing CLI or headless SDK
session without writing to that session.

Meta's field diagnosis attributed the black custom-launcher window to a
positional prompt forcing non-interactive execution, `--no-alt-screen`, and the
nested encoded-PowerShell wrapper chain. Carry that hypothesis forward, but note
that Codex CLI `0.145.0` help describes `[PROMPT]` as valid for the interactive
CLI, so the precise causal role of the positional prompt is **UNVERIFIED**. The
black-window symptom itself is verified.

## Operating rules learned the hard way

- **Never poll bridge tools in a loop.** Each uncached
  `orchestrator_status` path can spawn a PowerShell descendant probe. A six-second
  poll loop flashed windows repeatedly on the founder's desktop. Use one-shot
  checks and let the five-second descendant cache suppress repeated probes.
- **Deploy promptly.** Commits sat undeployed while the founder watched broken
  behavior. A fix in Git is not a fix in the running daemon.
- **Apply `windowsHide` at the correct boundary.** It must be `true` on every
  internal helper spawn except the one intentional visible console. The
  `wt.exe` spawn is the window, not a wrapper; hiding it hides the intended UI.
- **Green tests do not prove human-visible rendering.** The suite passed while
  the founder saw a black window. Only the founder's screenshot exposed the
  rendering failure; human-visible features need visual verification.
